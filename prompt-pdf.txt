What We Will Build
________________________________________
Before We Start Prompting
Trainer Explanation
Now that we understand what we are going to build, let's start developing the application using Cursor AI.
Instead of asking Cursor to generate the entire application in a single prompt, we will build it step by step.
This is an important approach when working with AI coding tools. We first give Cursor the basic requirement, review what it generates, and then progressively add more functionality.
Let's start with the basic application.
________________________________________
Prompt 1 — Create the Basic Blog Application
Trainer Explanation
First, we need to give Cursor the overall requirement.
At this stage, we don't need to provide every technical detail. We simply tell Cursor what application we want to build and the main functionality.
Let's see how Cursor understands our requirement and creates the initial application.
Cursor Prompt
Create a simple Blog application using Python and FastAPI.

Requirements:
- Use FastAPI for the web application.
- Use SQLite for storing blog posts.
- Users should be able to view, create, update, and delete blog posts.
- Use HTML templates for the web pages.
- Keep the application simple and easy to understand.
- Create a clean project structure.
- Create requirements.txt with the required dependencies.

First create the project structure and basic implementation.
After Cursor Generates the Code
Trainer says:
Let's stop here and review what Cursor has created.
We should not blindly accept AI-generated code. As developers, we need to understand the generated structure and implementation.
Let's check the main application file, templates, database configuration, and dependencies before running the application.
________________________________________
Prompt 2 — Create the SQLite Database
Trainer Explanation
Our basic application is ready. Now we need to define how blog posts will be stored.
We will use SQLite because it is lightweight and does not require a separate database server.
Each blog post should contain basic information such as title, content, author, and creation date.
Let's ask Cursor to add the database layer.
Cursor Prompt
Now add SQLite database functionality using SQLAlchemy.

Create a BlogPost model with:
- id
- title
- content
- author
- created_at

Requirements:
- Configure SQLite using SQLAlchemy.
- Create the database automatically when the application starts.
- Keep database configuration separate from the API routes.
- Use the BlogPost model for database operations.
- Do not remove the existing functionality.
Trainer Explanation After Generation
Notice that we are not asking Cursor to recreate the entire application.
We are giving it a new requirement and asking it to modify the existing project.
This is one of the important benefits of using Cursor with an existing codebase.
________________________________________
Prompt 3 — Implement CRUD Operations
Trainer Explanation
Now our database is ready.
The next step is to connect the web application with the database and implement the actual CRUD operations.
Our users should be able to create a post, view posts, edit a post, and delete a post.
Let's ask Cursor to implement these operations.
Cursor Prompt
Implement CRUD functionality for BlogPost.

Requirements:
- Home page should display all blog posts.
- Add a page to create a new blog post.
- Add functionality to edit an existing post.
- Add functionality to delete a post.
- Add a page to view a single blog post.
- Use SQLAlchemy for database operations.
- Use Jinja2 templates for the HTML pages.
- Validate form input and handle basic errors.
- Follow the existing project structure.
Trainer Explanation After Generation
Now we have the core functionality of our application.
Let's run the application and test each operation:
Create → Read → Update → Delete
If something doesn't work, this is also a good opportunity to demonstrate Cursor's debugging capability instead of manually searching through every file.
________________________________________
Prompt 4 — Improve the User Interface
Trainer Explanation
Our application is functional, but the interface is still basic.
In a real application, functionality is important, but the user experience is also important.
Let's now ask Cursor to improve the design without changing our backend functionality.
Cursor Prompt
Improve the UI of the existing Blog application.

Requirements:
- Use Bootstrap for styling.
- Add a clean navigation bar with Home and New Post links.
- Display blog posts using attractive cards.
- Create clean forms for creating and editing posts.
- Add buttons for View, Edit, and Delete.
- Create a responsive layout.
- Improve spacing, typography, and overall appearance.
- Do not change the existing backend or database functionality.
Trainer Explanation
Notice the last instruction:
"Do not change the existing backend or database functionality."
This is important when working with AI coding tools. We can clearly define the scope of the change.
________________________________________

Trainer Explanation
At this point, we already have a working Blog application.
Now let's add one useful feature to make the application more realistic.
Users should be able to search for posts and sort them by title or date.
Again, we don't need to explain how to implement it. We describe the requirement and let Cursor analyze the existing code.
Cursor Prompt
Add search and sorting functionality to the Blog application.

Requirements:
- Add a search box on the home page.
- Users should be able to search posts by title.
- Add sorting by title.
- Add sorting by creation date.
- Keep the existing CRUD functionality unchanged.
- Use SQLAlchemy queries where appropriate.
- Keep the implementation simple and readable.
Trainer Explanation
Here we are demonstrating another important Cursor capability:
Extending an existing application.
Cursor needs to understand our existing routes, models, templates, and database logic before making the changes.
